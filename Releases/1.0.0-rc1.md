# psh 1.0.0-rc1

**Performance SHell, based on Zsh 5.9.2.**

**Development draft: publication remains on hold.** The earlier prepared source
archive is a historical checkpoint and does not contain the new round 39 work.

rc1 brings compiler optimization profiles, guarded float formatting, full scene
benchmarks and stronger packaging and compatibility checks. It retains rc0's
27 core optimizations and adds one, alongside all six bundled projects: zdraw,
zjson, zcurl, zmdown, zhtml2md and zoup. Existing native ownership contracts remain;
an independent optional formatting acknowledgment preserves conservative fallback
for older modules.

## What's new

- **Less locale overhead when formatting floats.** Eligible queued string
  conversions use a private C locale while retaining libc's formatting rules.
  Unknown native modules and standard printf extensions retain the original
  converter, as do FILE callbacks and existing private thread locales. A real
  callback-breaking prototype was rejected before adopting the guarded path.
- **Optional GCC PGO and LTO builds.** Checked bundled workloads train an isolated
  build before its final compilation. Your scene and simulation projects are
  held out of training. Compiler identity, training inputs and feedback hashes
  are recorded. Ordinary builds remain the default.
- **Safe completion directory permissions under umask 0002.** Packaging fixes
  group-writable parent directories that made compinit reject an installation.
  Completion security checks stay enabled; personal/source permissions are not
  changed.
- **A consistent Oh My Zsh gate.** All 24 sessions now run even when the test
  launcher is Bash and does not export FPATH. Framework code, themes, plugins,
  highlighting and personal startup files remain unmodified.
- **Stateful compatibility coverage.** Reproducible mutation sequences check
  arrays, dynamic scope, Unicode, redeclarations and arithmetic-error recovery,
  including exact diagnostics and focused memory checks.
- **Full scene benchmarks.** Alpine Vigil, Moonlit Vigil, Faerie Pool, Profile
  Study, Per Arne and Emerald Rings now have a psh-owned driver that checks every
  palette and material/depth output value. Native build caches are isolated.

## Additional core gains over the compiler-only rc1 checkpoint

The final round 39 candidate takes about **9.5% less time for Moonlit Vigil**,
**3.7% less for Alpine Vigil** and **3.3% less for Faerie Pool** than the previous
optimized rc1. The other three scenes are essentially flat (under 1% change).
Mario and the three shooter simulation kernels also improve; editor layout,
Endgame and drawing binning remain broadly flat. Complete checked states match.

These are separate comparisons against the preceding PGO+LTO build, not a
directly measured cumulative speedup over public rc0. The
[round 39 report](../Perf/round39.md) retains all individual results, the
same-executable legacy-converter control, repeats and native compatibility tests.

## Compiler-profile measurements against rc0 (round 38)

The earlier compiler-only **PGO+LTO** checkpoint takes about **10–12% less
construction time** across all six scenes on this host:

| Scene | rc0 → rc1 construction | Less time |
| --- | ---: | ---: |
| Alpine Vigil | 26.86 → 23.97 s | 10.7% |
| Moonlit Vigil | 6.16 → 5.50 s | 10.8% |
| Faerie Pool | 19.63 → 17.66 s | 10.0% |
| Profile Study | 5.57 → 4.91 s | 11.9% |
| Per Arne | 14.10 → 12.49 s | 11.4% |
| Emerald Rings | 16.97 → 15.14 s | 10.7% |

Editor paste takes about 16% less time, Endgame about 15%, and URL encoding
about 18% in two nine-sample comparisons. Every checked result state matches.
Scene timings use five alternating fresh-process samples per host, an excluded
warmup and complete rendered-output comparisons; a separate Moonlit repeat
confirms the direction. The scenes and simulations are held out of compiler
training. Cached launches and interactive frame rates are not measured here.

The host is an AMD Ryzen 9 5950X running Mageia, with GCC 15.2.0. Results are
specific to these workloads and build settings; [raw evidence](../Perf/results/round38/README.md)
includes ordinary, LTO, PGO and combined pilots, slower controls and repeats.
The tuned executable is 883,312 bytes versus rc0’s 854,680 bytes (3.4% larger);
debugger symbols remain separate.

## Build the optimized distribution

The compiler-profile gains require an optimized packaged build. From the current
rc1 development checkout, the GCC PGO+LTO configuration evaluated here is:

```sh
python3 Packaging/build.py --optimization pgo-lto
```

Then follow the [installation and verification workflow](../Packaging/README.md).
The build itself stages a package; it does not activate a shell. Training uses
bundled offline sources, with no personal startup files or network services.

`--optimization pgo` offers profile feedback without LTO. The default
`--optimization standard` retains the ordinary compiler flags. These are distinct
builds; a plain `Perf/build.py` core trial does not acquire the measured PGO/LTO
gains. See the guide for dependencies, compiler support and debugger symbols.

## Compatibility and validation

`psh --version` reports `psh 1.0.0-rc1 (zsh 5.9.2)`. `$ZSH_VERSION` stays 5.9.2,
stock modules keep their `zsh/*` names, and personal Zsh startup filenames retain
their meaning. Versioned private paths preserve stable Zsh and older psh builds.
Existing processes keep their original modules when a new release is activated.

The optimized candidate passes 63 upstream scripts with zero failures and two
skips, all seven package suites, 24 unchanged OMZ sessions and the additional
differential/native checks. These include 195,600 arithmetic comparisons across
five locales and stateful mutation/error-recovery sequences. The
[compiler investigation](../Perf/round38.md) and
[float-formatting investigation](../Perf/round39.md) retain methods, controls,
limitations and rejected attempts. The new native formatting oracle also checks
complete output and surrounding FP/errno/locale/callback/queue state.

The validated host is Mageia x86-64 with GCC 15.2.0. Compatibility with every
script, platform or independently compiled native module is not established.
Native modules should use the matching SDK and the existing
[ownership and fallback policy](../COMPATIBILITY.md). No arithmetic JIT or
execution-plan cache is introduced in rc1.

Report regressions with a minimal reproducer, both shell versions, locale and
options, expected/actual output and status, and `psh-config --build-id` at the
[issue tracker](https://github.com/ZaguanLabs/psh/issues).

Published rc0 and the earlier private checkpoint remain preserved. Upstream and
component notices remain intact; see [LICENCE](../LICENCE), [LICENSE](../LICENSE)
and the bundled vendor notices. Thanks to the Zsh contributors and to everyone
testing psh in real applications.
