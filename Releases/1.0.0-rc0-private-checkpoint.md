# psh 1.0.0-rc0 (zsh 5.9.2)

Experimental source release candidate for a Zsh 5.9.2 performance fork.
The compatibility target is upstream Zsh's language and public module
interfaces. **100% drop-in compatibility has not been established.**
[Intentional differences and the regression policy](../COMPATIBILITY.md) are
part of this release. Unknown failures outside the author's projects matter.

## Identity and contents

```text
psh --version                 psh 1.0.0-rc0 (zsh 5.9.2)
psh -dfc 'print $ZSH_VERSION'  5.9.2
psh-config --version          1.0.0-rc0
psh-config --zsh-version      5.9.2
```

The release contains the nineteen accepted optimizations through
[round twenty](../Perf/round20.md), the separately backported upstream scalar
search bounds fix, and pinned zdraw, zjson, zcurl, zmdown, zhtml2md and zoup
sources. This RC adds project identity, split debugger symbols and release/test
infrastructure; it adds no new language optimization beyond that accepted set.

Module identities and the module/function directory version remain Zsh 5.9.2.
The private installed build is `1.0.0-rc0-13aa87c312a1`. Its source/settings ID
is available through `psh-config --build-id`. No new `PSH_VERSION` shell
parameter is reserved. Standard `is-at-least` checks continue to use 5.9.2.

## Why the executable was three times larger

| Executable on the validation host | File bytes |
| --- | ---: |
| Installed system Zsh, stripped | 905,856 |
| Previous installed psh, with embedded symbols | 2,722,816 |
| RC psh, stripped with a debug link | 891,544 |

The old difference was predominantly debugger information and symbol tables.
The RC's code/data/BSS total reported by `size` is **960,817 bytes**, versus
**963,031** for the system Zsh. These are ELF image measurements, not whole
process RSS or an assertion of identical build flags. System Zsh is PIE; the
current psh build retains its existing non-PIE configuration and debug assertions.

The RC keeps debugger information in `bin/.debug/psh.debug` (**1,985,664 bytes**).
Every allocated section, entry point and dynamic exported name/type is checked
against the unstripped build. GDB's automatic debug-link discovery resolves
source lines successfully. Native modules retain their exact tested bytes.
Keeping symbols separately does not imply the same reduction in total install
space. The base-version executable alias now points to the same `psh` file.

## Known debug-profile difference

This RC retains the assertion-enabled development profile. With `TERM` unset
or invalid, `zmodload zsh/termcap; zmodload zsh/terminfo` prints an
`inconsistent term_count and/or cur_term` assertion diagnostic. The matched
pristine debug build does the same; the installed non-debug system Zsh is
silent. This is a concrete stderr difference from that system installation.
[The reproducer and comparison](results/1.0.0-rc0/terminal-environment.json)
are recorded. The first extracted-archive test exposed it because the checker
omitted `TERM`; that failed run is retained. The checker now supplies `TERM=xterm`,
and the focused upstream module-loading suite passes for both builds.

## Compatibility evidence

Validated here on Mageia Linux x86-64, glibc 2.42, GCC 15.2.0 and Clang 20.1.8,
using `-O2 -g` and Zsh debug assertions. The source/settings ID is not a claim of
identical binaries across different compilers or operating systems.

- GCC development build: **62 upstream scripts pass**, zero failures, three
  expected skips. The no-multibyte substitution, conditional and arithmetic
  checks pass as well.
- Exact stripped installed ELF: **63 upstream scripts pass**, zero failures,
  two expected skips. All six bundled project suites pass, including **190
  zdraw tests**. Installed change-gutter rendering and login startup pass.
- Clang: matched pristine and psh builds each pass **63 upstream scripts**,
  with two expected skips. **66,060 syntax comparisons**, **281,834 scalar
  comparisons**, **63,840 pattern comparisons** and **200,832 native numeric
  scenarios under Memcheck** pass.
- GCC focused comparisons retain **110,100 syntax**, **704,585 scalar**,
  **5,192 array**, **193,236 search**, **159,600 pattern** and **2,640
  substitution** checks. Custom accessor callbacks and real PTY completion
  buffers match. Normal and no-multibyte builds each pass **535,552 native
  numeric scenarios**; no-multibyte syntax and scalar comparisons pass too.
- The installed RC itself matches pristine in another **110,100 syntax
  comparisons**, **704,585 scalar comparisons across five encodings** and
  **200,832 native numeric scenarios**. French Belgian UTF-8 and Latin-1 add
  **44,040 syntax comparisons** and **133,888 native numeric scenarios**.
  Memcheck reports zero memory errors; leak checks are disabled.
- All **32 generated public declaration files** and **1,055 exported
  names/types** match the respective pristine build for both GCC and Clang.
  `Src/zsh.h`, which defines the core data structures, is unchanged.
- Option listings match pristine for eight invocation names, including `psh`,
  native Zsh, sh/ksh and restricted forms. These check Zsh's invocation modes,
  not compatibility with a different shell implementation. Inherited `FPATH`
  remains honored. A header-only project version bump triggers an incremental
  rebuild with the correct new version string.

[Recorded results](results/1.0.0-rc0/) include exact commands, source and binary
hashes, compiler/configuration context and initial setup failures. They describe
those cases, not every possible script. Wider OS/libc coverage, all user startup
configurations and third-party modules remain unverified.

The core package test path was strengthened for this RC. Earlier package core
runs used the build-tree executable, whose bytes matched the installed copy;
that was narrower than directly exercising an installed executable. The new
harness routes upstream hardcoded executable/module paths to the actual
installed files, through an alias named `zsh` for diagnostic expectations.
Direct `psh` identity and startup are checked separately. Its first setup attempt
found the source filename `param_private.so` differs from the installed name
`zsh/param/private.so`; the mapping now uses `config.modules`. The affected suite
passed on retry, and the initial failure is retained.

## Building and installing

Use the attached `psh-1.0.0-rc0.tar.xz` asset. It contains the verified original
upstream baseline needed for comparisons; GitHub's automatic source snapshots
lack that extra archive. The attached archive builds without Git history.

```sh
tar -xf psh-1.0.0-rc0.tar.xz
cd psh-1.0.0-rc0
python3 Perf/build.py
./psh --version
```

This is a private development/core build. For the complete bundled installation,
use [the installation workflow](../Packaging/README.md) and its dependency list.
The packaging workflow is currently validated on the Linux host above. Source
builds on other systems remain experimental. Source archives and checksums do
not promise a prebuilt binary will work with another distribution's libraries.

The release tarball includes source commit/tree metadata and all 1,847 verified
baseline files inside its embedded original-source archive. The source-release
checker extracts outside Git, disables Git during compilation, builds both
core variants, runs the core suite and stages the full bundled package without
installing that separate rebuild. Its report accompanies the release assets.

All **11,828 protected Zsh/startup entries**, `/etc/shells`, the account login
shell and the preceding installed release remain unchanged. Existing psh
sessions retain their old matching modules. Start a new psh process to use this
candidate. The repository's visibility is unchanged; the candidate can be
reviewed as a draft before public release.
