# psh 1.0.0-rc2

**Performance SHell, based on Zsh 5.9.2. A public maintenance release.**

rc2 fixes an installation gap that could leave a fresh psh session without its
normal locale or personal command directory. Programs such as `btop` could report
“No UTF-8 locale detected” or appear to be missing even when installed in `~/bin`.
The same account worked correctly under system Zsh.

This was psh startup integration, not a Kitty terminfo problem or a change in
Zsh's language semantics. psh correctly used its isolated global configuration
directory, but the installation workflow supplied no distribution environment
initialization there.

## What's fixed

- **Explicit host startup setup.** The installer can preview and create missing
  global startup files under `/usr/local/psh/etc`. Mageia receives its interactive
  PATH and locale initialization; AlmaLinux receives its login PATH setup and
  login/non-login locale initialization. The distribution's own locale helper
  selects the locale. psh does not hardcode UTF-8 or override the helper's policy.
- **Existing configuration is preserved.** Files and symlinks are never
  overwritten, including empty administrator-created files. Creation is atomic
  and refuses a destination that appeared after preview. Global configuration
  remains outside versioned releases and survives upgrades.
- **A gate for the environment users actually receive.** Verification compares
  63 locale/PATH cases against system Zsh, covering inherited and unset locale
  values, LC overrides, login and interactive combinations, and disabled startup.
  It checks the character map visible to child processes and executes a command
  found through `~/bin`.
- **Oh My Zsh with global startup enabled.** The existing 24-session terminal
  gate now includes actual global startup files. Completion, history, prompt,
  highlighting, async behavior and interpreter handoffs are exercised with the
  configured framework stack. Framework and personal startup files stay untouched.
- **Activation requires current evidence.** The installer rejects missing,
  failed or stale startup reports, including changes to tested startup inputs.
  A regression test reproduces rc1's missing-global failure and confirms that
  the new environment gate rejects it.

The earlier tests disabled global startup and supplied a UTF-8 locale. They
tested interpreter/framework behavior but missed this host integration gap.
Those limitations are now covered explicitly.

## Upgrade: the configuration step matters

Download **`psh-1.0.0-rc2.tar.xz`** from the release assets. It includes the
verified Zsh baseline; GitHub's automatic source snapshots do not include that
embedded baseline. Build and install using the [packaging guide](../Packaging/README.md).

The workflow now includes these commands, before verification and activation:

```sh
python3 Packaging/install.py startup
sudo python3 Packaging/install.py startup --apply
```

The first command previews the files and their contents. The second creates
only missing files. If you already have custom psh global startup files, review
and merge the relevant environment setup yourself; the installer preserves them.
If the earlier host repair was already applied, it is retained without adding
duplicate hooks. Replacing only the executable does not repair missing startup
configuration.

Start a new psh session after the configuration change. Existing terminals keep
their previous environment. These host defaults also work with existing rc0/rc1
installations; binary rollback does not revert shared startup configuration.

Automatic defaults are deliberately limited to **Mageia and AlmaLinux**.
Other distributions require a review of their system Zsh startup policy and
private psh configuration. No guessed universal locale or full `/etc/profile.d`
import is installed. Unrelated system aliases, prompts and key bindings are
outside this fix's scope.

## Compatibility and validation

The 30 accepted core optimizations and all six bundled projects are unchanged
from rc1. `$ZSH_VERSION` remains `5.9.2`, module names and native interfaces retain
their identities, and `--version` reports `psh 1.0.0-rc2 (zsh 5.9.2)`.
There are no new language incompatibilities or performance claims in this release.

The original host repair was checked on local, fidelity, spiffle and phoenix:
144 environment comparisons matched system Zsh, actual `btop` binaries opened
and exited without force-UTF options under both shells, and 96 Oh My Zsh terminal
sessions passed. System Zsh, personal startup files, framework sources and
account login-shell records were unchanged. These are repair results on rc1;
the attached rc2 validation evidence records the release candidate separately.

Published rc0 and rc1 tags and archives remain unchanged. Universal script and
platform compatibility is not claimed; please report regressions with shell
versions, distribution, relevant locale variables and a minimal reproducer.
Keep private startup files and credentials out of public reports.
